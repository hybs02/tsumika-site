Claude CodeでKindle本を「半自動」で量産する：実際のworkflow

執筆： hybs02

KDPKindle出版AIClaude Code

「AIでKindle本を量産」と聞くと、ボタンひとつで売れる本が湧いて出るような印象を持つかもしれません。実際にKDPの制作を自動化してみた結論を先に言うと、それは無理。でも、作業量を大きく減らすことは確実にできます。大事なのは「どこをAIに渡し、どこを人間が握るか」の線引きです。

なぜ「全自動」が成り立たないのか

KDPで本が埋もれる一番の原因は、中身が薄いこと。AIに丸投げして出てきた原稿をそのまま出すと、まさにこの「薄い本」になります。低評価がつき、誰にも読まれず終わる。

つまり、企画の良し悪しと品質チェックだけは、人間が握らないと成立しない。逆にそこさえ握れば、執筆・整形・表紙づくりの重労働は丸ごと渡せる。これが「半自動」の正体です。

工程の分担（実際にこう分けた）

制作の流れを、AI担当と人間担当で割るとこうなります。

人間が握る

  • 市場調査と、どの隙間を狙うかの判断
  • 差別化の方針（既存本に無い切り口を1つ決める）
  • 最終的な品質チェックと推敲

AIに任せる

  • 決めた方針に沿ったアウトライン作成
  • 各章の下書き執筆
  • 整形やEPUB化のための機械的な処理

ポイントは、AIに渡す前に「誰の、どんな悩みを、どう解決する本か」を人間が一文で決めておくこと。ここが曖昧なまま投げると、それっぽいだけの中身のない原稿が返ってきます。

つまずきやすいところ

一気に全部出させない

「本を1冊書いて」と一発で頼むより、章ごとに方向性を確認しながら進めたほうが、結果的に品質が安定して速い。ズレたまま最後まで書かれると、直す手間のほうが大きくなります。

生成物を信じすぎない

事実関係や具体例は、人間が確かめる前提で。スラスラ出てくるぶん、検証を飛ばしたくなりますが、ここを省くと信頼を落とします。

守らないと危ない、プラットフォーム側のルール

AIで本を作るなら、Amazon側のルールを把握しておく必要があります。ここを軽視すると、本が消えるどころかアカウントごと止まる可能性があります。

押さえておくべき点は主に3つです。

1つめは、AI生成の申告義務。出版・再出版のときに「AIが生成した本文・画像・翻訳が含まれるか」を申告する項目があります。AIツールで作った内容は、あとから大幅に手を入れても「AI生成」に当たるとされています。

申告内容は購入者には見えず、印税や検索順位にも影響しないと案内されています。つまり隠す理由がない。逆に未申告が発覚すると、削除やアカウント停止のリスクがあります。

なお、人間が書いた文章に対する校正や壁打ちのような「AI補助」は、申告の対象外とされています。

2つめは、1日に出せる新規タイトル数の上限。AIによる大量投稿への対策として、1日あたりの新規タイトル数に制限が設けられています。量産のペースは、この枠内で組む必要があります。

3つめは、品質そのもの。「購入者をがっかりさせる内容」は明確に禁止されています。既存情報の寄せ集め、誤訳、無料で手に入る情報をまとめただけのもの。こうした本は削除対象です。

ルールは変わることがあるので、出版前に必ず公式の最新のガイドラインを確認してください。この記事の内容は執筆時点のものです。

実際にやってみて感じたこと

工程を分けてAIに渡す形にしてから、1冊にかかる時間は明確に短くなりました。特に短縮効果が大きかったのは、アウトラインから下書きを起こす部分です。

一方で、時間が減らなかった工程もあります。企画と最終チェックです。むしろ、生成が速くなった分だけ、チェックすべき分量が増えて負担が上がった面もありました。

つまり「AIを入れれば全工程が楽になる」わけではなく、楽になる工程と、変わらない工程がはっきり分かれるというのが実感です。楽になった時間を、そのまま企画と品質チェックに再投資できるかどうかで、結果は変わってくると思います。

量産を成り立たせるコツ

  • 1冊入魂より、型を作って回す。2冊目以降は同じ手順を流用できる
  • シリーズ化して関連本を並べる。1冊が当たると横展開で売れる
  • 売れ筋が見えたら、そのジャンルに資源を寄せる

向いているジャンル、向いていないジャンル

やってみて感じた相性の差も書いておきます。

向いているのは、手順や知識を整理して伝えるタイプです。何かのやり方、入門的な解説、体系立てて説明できるもの。こうしたジャンルは構成が組みやすく、AIの下書きも使いやすい。

向いていないのは、書き手固有の体験や人格が価値になるものです。エッセイ、体験記、独自の主張。これらは「誰が書いたか」が中身そのものなので、AIに任せる部分がほとんど残りません。

そして皮肉なことに、前者は競争が激しく、後者は競争が少ない。効率よく作れるジャンルほど、同じことを考える人が多いわけです。ここをどう考えるかが、量産で埋もれるかどうかの分かれ目だと思います。

まとめ

AIはKDPの執筆・整形という重労働を肩代わりしてくれます。握るべきは「企画」と「品質」。この線引きさえ外さなければ、1冊にかかる時間は劇的に縮みます。Kindle以外の収益化と組み合わせる発想は AIで副業を自動化する方法 に、道具としての Claude Code の解説も合わせてどうぞ。
